# Modul `servicedesk` (05-servicedesk.mjs): tiket, persetujuan, work order, laporan, knowledge base

File: `scripts/demo/05-servicedesk.mjs` + pembantu `05-servicedesk-engine.mjs` (memainkan tiket lewat API, lalu memundurkan waktunya dengan SQL), `05-servicedesk-time.mjs` (kalender kerja dan jam SLA, salinan persis dari `WorkingCalendar`/`SlaClock` di API), `05-servicedesk-data.mjs` (± 100 tiket dalam Bahasa Indonesia), `05-servicedesk-kb.mjs` (knowledge base).
Dijalankan sendiri: `node scripts/demo-seed.mjs --api http://localhost:<port> --db <db> --only servicedesk` (setup otomatis dijalankan dulu; tanpa modul assets/stock modul ini membuat vendor, pusat biaya dan baris biaya "part" manual sendiri). Waktu: ± 70 detik pada database kosong, ± 3 detik pada run kedua (idempoten: tiket dilewati kalau tiket penanda "AC ruang Merak berisik dan bergetar" sudah ada; tampilan tersimpan, delegasi, artikel KB, jadwal laporan dicari per nama).
Semua data dibuat lewat API sebagai tokoh demo (rizky/anita/fajar/lina/dimas sebagai pemohon; putri, hendra, agus, bayu, joko sebagai pekerja; admin untuk legal hold). SQL dipakai hanya untuk memundurkan waktu (lihat bagian terakhir).

Angka di bawah adalah hasil run lengkap pada hari seeding (`spaces, assets, stock, servicedesk`); semua tanggal relatif terhadap hari seeding.

## Not demonstrable / bugs / caveats

- **Keadaan SLA relatif terhadap jam seeding**: tiket "at risk" punya sisa waktu 7–15 % dari targetnya (beberapa jam kerja) dan akan menjadi "overdue" dengan sendirinya (worker SLA berjalan tiap 5 menit dan menghitung ulang; sudah diuji: hasil hitung worker identik dengan yang disimpan seed, kecuali tingkat eskalasi yang naik seiring waktu). Seed paling baik dijalankan pada hari/pagi demo.
- **Tiket "menunggu konfirmasi" ditutup otomatis 3 hari setelah selesai** oleh worker (tiap jam). Tiket-tiket itu selesai 8–40 jam sebelum seeding, jadi demo sebaiknya dalam ± 40 jam setelah seeding.
- **Aturan routing "All requests" = least loaded**: tiket baru layanan tanpa aturan khusus (ATK, kurir, kartu akses…) langsung ditugaskan ke anggota GA dengan beban paling sedikit (Putri; Hendra 4, Putri 3, Agus/Bayu > 10). Tiket "tanpa penanggung jawab" di antrean adalah yang dikembalikan ke antrean tim dan layanan **Visitor registration** (aturan Reception = tanpa strategi). Untuk memperagakan "tiba tanpa penanggung jawab" secara hidup, buat permintaan *Visitor registration*.
- **Bug/kejanggalan setup (01-setup)**: kebijakan SLA khusus ("Server room: any request", "Air conditioning faults", "Warehouse requests") dibuat *setelah* empat kebijakan umum berdasarkan prioritas; karena "yang pertama cocok menang", kebijakan khusus tidak pernah dipakai. Modul ini mengurutkan ulang lewat `POST /api/sla/policies/reorder` (khusus di depan) sebelum membuat tiket. Server room sekarang 10 menit respons / 2 jam penyelesaian pada kalender 24/7.
- Log audit (`/audit`) **tidak digeser**: tabel `audit_events` append-only (trigger menolak UPDATE). Semua aksi tiket dicatat di sana berstempel hari seeding, sementara timeline tiket dan notifikasi berstempel sesuai riwayat.
- Baris eskalasi SLA di timeline tiket dan notifikasi "SLA at risk/breached" untuk tiket yang sedang berjalan dibuat **dengan INSERT** (API hanya membuatnya lewat worker), berstempel saat ambang terlewati.
- Legal hold butuh re-autentikasi: seed memanggil `POST /api/auth/reauth` sebagai admin dengan kata sandi demo, lalu `PUT /api/tickets/{id}/legal-hold`.
- Nomor tiket: tiket pemeliharaan (modul assets) memakai nomor pertama; tiket modul ini bernomor lebih besar walau tanggalnya (setelah dimundurkan) bisa lebih lama. Di dalam modul ini nomor mengikuti urutan tanggal.
- `ticket_approvals.token_expires_at` untuk persetujuan menunggu tidak digeser (link email berlaku 7 hari dari seeding, bukan dari pembuatan semu).
- Bagian "Part dari stok": 9 baris diambil dari stok modul stock (gerakan issue, stok berkurang); bila barang tidak cocok/ habis dipakai baris biaya "part" manual. Anggaran modul stock harus **dikalibrasi ulang setelah modul ini** (`--only stock` sekali lagi atau `calibrateBudgets(d)`), supaya persentase penggunaan anggaran memakai biaya work order ini.
- Tidak diverifikasi di UI Next.js, hanya lewat API sebagai persona yang membuka layar (angka di atas dibaca ulang dari `/api/tickets`, `/api/reports/*`, `/api/costs/report`, `/api/approvals/mine`, `/api/work-orders*`).

## Backdating done (SQL, hanya baris yang dibuat modul ini)

- Setiap tiket dimainkan lewat API (waktu "sekarang"), lalu **semua baris turunannya digeser** ke momen yang dimaksud skrip: `tickets` (created_at, updated_at, assigned_at, first_responded_at, resolved_at, closed_at, cancelled_at), `ticket_events`, `notifications` (created_at, dan read_at: yang > 16 jam lalu ditandai terbaca kecuali persetujuan yang masih menunggu dan tiket "resolved" yang belum dikonfirmasi), `ticket_approvals` (created_at, decided_at), `ticket_ratings`, `attachments` (foto tiket dan foto before/after WO), `work_orders` (created/updated/started/completed), `work_order_tasks.done_at`, `work_order_times.created_at`, `work_order_costs.created_at`, `stock_movements.at` (part dari stok). Pemetaan memakai "tanda" waktu nyata tiap panggilan API, jadi urutan kejadian tetap benar.
- **Kolom SLA tiket** ditulis ulang sesuai yang akan disimpan API seandainya semuanya terjadi saat itu: `sla_start_at`, `sla_paused_at`, `sla_paused_minutes` (menunggu persetujuan dan on hold), `first_response_due_at`, `resolution_due_at`, `sla_state` (OnTrack/AtRisk/Breached/Paused/Met/None), `sla_escalation_level`, `sla_breached_at`; kalender mengikuti kebijakan (jam kantor, server room 24/7, gudang Senin–Sabtu, libur nasional).
- Diperkenalkan dengan INSERT: baris eskalasi SLA (`ticket_events`, kind Escalation) dan notifikasi SLA untuk tiket yang masih berjalan.
- `kb_articles` (created_at, updated_at, published_at, views, deflections) dan `kb_article_versions.created_at`: artikel tersebar 0–160 hari ke belakang; jumlah baca dan "this solved it" diisi langsung (counter di API hanya naik satu per kunjungan).
- Tidak digeser: `audit_events` (append-only), `outbox_emails`, `report_schedules` (jadwal dibuat hari ini; "Send now" sudah dijalankan sekali), `approval_delegations` (berlaku sejak 5 menit sebelum seeding sampai 5 hari kemudian), `ticket_views`.
